## 一、基础设施（utils/utils.ts）

### 1.1 HTTP 拦截 hookHttpRequest / hookAndModifyHttpResponse

**算法流程**（utils.ts:50-174）：

1. 模块级单例 `hooksInitialized` 保证 `XMLHttpRequest.prototype.open` 只被替换一次。
2. 替换后的 `open(method, url)`：
   - 遍历 `httpHooks` Map，若 `url.includes(urlMatch)`，则在当前 XHR 上追加 `readystatechange` 监听；
   - `readyState === 4 && status === 200` 时解析 `responseText`（`{` 开头按 JSON，否则原样字符串），依次调用注册的 `callback(response, context, url)`；
   - 遍历 `modifyHooks`，命中后在 readystatechange 中改写实例属性：`Object.defineProperty(xhr, 'responseText'/'response', { get: () => modifiedText })`，实现响应篡改；
   - 最终调用原始 `originalOpen.apply(this, arguments)`，不改变真实请求行为。
3. `hookHttpRequest(urlMatch, callback, context)` 仅向 Map 注册回调（异步立即 resolve）。

**注意点**：`hookHttpRequest` 按 `urlMatch + context` 去重（同 context 重复注册直接跳过并记"跳过重复注册"日志，防止重复 Init 回调扇出）；`removeHttpRequestHook(urlMatch, context)` 支持按 context 注销。同一请求 URL 命中 N 个钩子时各回调执行 1 次。需要"重新武装"语义的调用方（如 gatetask 拦截的可重入等待）必须先注销旧钩子再注册，否则新回调被去重跳过、旧回调作废后请求会被吞（T-019）。

### 1.2 TimerManager（utils.ts:286-327）

以 `Map<string, timeoutId|intervalId>` 按命名 key 管理 setTimeout/setInterval；`setTimeout/setInterval` 前先清理同名 key（幂等）；`clearAll()` 清空全部。所有 zsgl 业务类持有私有实例，`Stop()` 时统一释放。

### 1.3 事件阻止（utils.ts:226-281）

- `setupEventPrevention(target)`：对 window/document/元素以捕获阶段注册 `blur/resize/visibilitychange/fullscreenchange/focus/webkitfullscreenchange/mouseout/mouseleave/focusout/focusin/pagehide/pageshow/beforeunload/freeze/resume` 共 15 类事件的处理器，处理器内执行 `stopImmediatePropagation + stopPropagation`，切断平台"切屏检测"监听。
- `setupVideoEventPrevention(video)`：对 `seeked/seeking/ratechange/volumechange` 做同样阻止，掩盖倍速/静音篡改痕迹。
- `setupSwitchScreenNeutralizer()`（2026-09 新增）：用 `Object.defineProperty` 把 `window.onblur/onfocus/onresize` 的 setter 置为 no-op（模块级 once-guard）。事件阻止拦不住**属性赋值**方式的检测——站点在 `queryCourseDetail.do` 返回 `isOpenSwitchScreen:1` 时以 `window.onblur = fn` 装切窗检测（deobfuscated.js L1832-1874），超限直接终止学习任务；本函数与 course.ts 的响应改写（§3.1 第 4 条）构成双保险。
- `setupVisibilitySpoof()`（2026-09 新增）：重写 `document.hidden` / `document.visibilityState`，伪装页面始终可见，对抗基于 Page Visibility API 的暂停检测。
- 已知副作用：自身监听（如 keep-alive 的 visibilitychange、ratechange 防重置）也注册在同一目标上，捕获阶段顺序决定其是否被阻断。

### 1.4 DOM 工具

- `findElementByText(tagName, text)`：全量 `querySelectorAll(tagName)` 后按 `textContent.includes(text)` 线性查找首个命中元素（course 任务卡、播放入口依赖此函数）。
- `waitForElement(selector, {timeout=10000, interval=500})`：轮询查找，超时返回 null。
- `createStorageHandler(key)`：storage 事件处理器；`event.key === key` 且新值 `status === "finished"` 时移除自身并 `window.location.reload()`（学习地图任务完成后的回环入口）。
- `sendApiRequest(method,url,params,body,headers,timeout=30s)`：AbortController 超时控制的 fetch 封装，`credentials:"include"`，统一返回 `ApiResponse{success,data,error,status}`。

## 三、课程任务集（course.ts）

### 3.1 ZsglCourse.Init()（course.ts:43-87）

1. 注册 `courseTaskComplete` 事件 → 触发 `notifyStudyMapCourseComplete()`。
2. `setupCloseCourseListener()`：注册 storage 监听 + 3s 轮询，双通道检测 `zsgl_close_course_{courseId}` 键值为 `{status:"close"}`；命中后移除该键、`Stop()` 全部任务、`window.close()`，1s 后仍存活则 `alert('学习积分已达上限，请关闭此页面')`。
3. `hookCourseDetailRequests()`（course.ts:93-163）：
   - 拦截 `queryCourseDetail.do`，读取 `body.courseId`、`body.courseFileArr`；
   - `courseFileArr.every(hasLearned==="1")` 或数组为空 → `callEvent("courseTaskComplete")`；
   - 否则映射为 `CourseDetailItem[]`（补 courseId、jobIndex=index、playTime/learnedDuration）并 `filter(hasLearned==="0")` 存入 `courseDetailData`。
4. 切窗检测响应改写（2026-09 新增）：经 `hookAndModifyHttpResponse(QUERY_COURSE_DETAIL, ...)` 把响应体 `body.isOpenSwitchScreen / body.isOpenScreenShot` 改写为 0（幂等守卫 `switchScreenHooked`），从源头关闭站点切窗/截屏检测开关；与 utils 层 `setupSwitchScreenNeutralizer()`（§1.3）构成双保险。
5. `load` 事件或页面已就绪时：调用 `OperateCard()`，并以 `first` 标志保证 Promise 仅 resolve 一次。（原"在 `#watermarkFrame`/body 顶部插入占位 div"已移除——该 div 无实际用途，且疑似站点水印组件 `getIsWatermark` 抛 `removeChild` TypeError 的触发源。）

### 3.2 OperateCard / processCourseData / buildTasks

- **OperateCard**（course.ts:294-318）：数据为空时启动 `waitForData` 轮询（1s 间隔，20 次上限）等待拦截回调填充；超时则 `courseTaskCompleteFc()` 放行。数据就绪 → `processCourseData()`。
- **processCourseData**（course.ts:321-343）：以首个任务的 `fileName` 为锚点，`checkTaskDiv` 轮询（500ms 间隔，10 次上限）用 `findElementByText("span", fileName)` 找任务卡；命中 → `buildTasks()`、`taskIndex=0`、`callEvent("reload")`；超限 → 视为完成。
- **buildTasks**（course.ts:346-370）：按序遍历 `courseDetailData` → `TaskFactory.CreateCourseTask(value)`；返回 null（不支持的 cwType）则告警跳过；成功则赋 `jobIndex`、注册 `complete → callEvent("taskComplete", index, task)`、`await task.Init()` 入列。

### 3.3 任务调度与完成上报

- `Next()`（course.ts:277-287）：`taskList[taskIndex++]`；越界时 `courseTaskCompleteFc()`（发布事件 + 上报完成）。
- `notifyStudyMapCourseComplete`（course.ts:172-215）：遍历 localStorage，找到 `zsgl_task_{currentCourseId}` 键 → 改写为 `{status:"finished", expire}` → `window.close()`；未找到则告警。（`zsgl_daily_task_*` 前缀在同一循环中被匹配，但其 finished 改写仅针对课程键。）

### 3.4 翻页（保留能力）

`afterPage()/nextPage(num)`（course.ts:373-415）：基于 `.ncells/.currents/.orange01/.lock` 选择器的章节翻页逻辑；`nextPage` 对 `.lock` 存在的情况每 5s 重试，`num > 5` 时报"被锁卡住了"错误。当前主流程未调用（多任务卡片单页场景），为历史/兜底能力。

### 3.5 三方/混合课程分支与三节课毕业推送（2026-09-22 新增，ADR-001）

**三方课程识别**（hookCourseDetailRequests）：`courseFileArr` 含 `cwType === "URL"` 的任务即判定为三方/混合课程，本页不构建任务。

**自动化流程**（startThirdPartyFlow）：`isThirdPartyCourse && config.auto` 时轮询查找「立即学习」按钮（`findElementByText`，MUI 按钮需等待 React 挂载）并自动点击，打开 `lzlj.b.sanjieke.cn` 三节课学习页；三节课侧挂机由 sanjieke 模块完成（见 `.trae/specs/sanjieke-auto-study`）。

**完成判定 = 事件推送，不做服务端校验**。三节课页 `SanjiekeStudy.courseComplete()`（全部课时毕业）时双路通知 zsgl 课程页：

- **A 路 opener 直推**：`window.opener.postMessage({type:"sanjieke_course_complete", courseId}, "*")`，精准送达打开它的 zsgl 标签页；站点以 noopener/手动方式打开时 opener 为 null，自然失效。
- **B 路扩展中转**：sanjieke 页面脚本 →（window.postMessage 桥 `cxmooc-tools`）→ sanjieke start.js →（chrome.runtime.sendMessage）→ background →（chrome.tabs.sendMessage，优先 `sender.tab.openerTabId`，缺失时广播 `zsgl.lzlj.com` 标签页）→ zsgl start.js →（window.postMessage）→ zsgl 页面脚本。

**zsgl 接收**（course.ts `onWindowMessage`/`onSanjiekeCourseComplete`）：过滤消息类型（常量 `SANJIEKE_COURSE_COMPLETE_TYPE`，单一来源 `src/internal/utils/message.ts`）→ `sanjiekeCompleteHandled` 幂等去重（A/B 双路仅首次生效）→ `thirdPartyFlowStarted` 守卫（未启动仅告警忽略，防广播误达/手动打开误触发）→ 直接触发 `courseTaskCompleteFc()` 走既有闭环（写 `zsgl_task_{courseId}` finished + 关页）。

**历史方案（已移除）**：曾以 30s 轮询重放 `queryCourseDetail` 判定完成；因重放请求缺 `courseId` 请求体与 `headerMap` 签名头，服务端返回"后台处理错误"，校验失效，随本机制整体移除（`pollThirdPartyCourseStatus`/`thirdPartyPoll`/`courseDetailRequestUrl`/`THIRD_PARTY_POLL_INTERVAL_MS`）。被动 hook 的 `allCompleted` 判定（站点自身请求 course detail 时）保留不动。

**时序**：三节课侧通知先行、延迟 500ms 关页（`COMPLETE_NOTIFY_CLOSE_DELAY_MS`），防止页面销毁早于消息发出；关页失败仅告警，不影响 zsgl 侧闭环。

**页面保活（Web Lock）**：zsgl 课程页（三方流程）与学习地图页均无媒体播放、纯等待通知，后台挂机超过浏览器阈值（Edge 睡眠标签页 / Chrome 内存节省程序，默认 2 小时）会被冻结，冻结页 JS 停摆致推送延迟至解冻才处理。`setupPageKeepAlive()`（utils.ts）通过 `navigator.locks.request(KEEPALIVE_LOCK_NAME, {mode:"shared"}, 永不 resolve)` 持锁，使页面进入冻结豁免名单；锁随页面销毁自动释放。调用点：`startThirdPartyFlow()` 开头、`ZsglStudyMap.Init()` 开头。`navigator.locks` 不可用时静默跳过（退化为"解冻后闭环延迟"，通知不丢失）。三节课页与普通课程页不加锁（视频播放即豁免，ended 间隙为分钟级）。用户级双保险：浏览器"始终保持活动"站点名单设置指引见 08-用户指导 §五。

## 五、视频任务（video.ts）

### 5.1 生命周期

```
Init()  : findElementByText('span', fileName) 找任务卡 + querySelector('video#course-video_html5_api')
          两者齐备 resolve，否则 reject(TASK_NOT_FOUND)
Start() : setupVideoEndHandler() → setupEventPrevention(window/document/video)
          → startKeepAlive() → taskDiv.addEventListener('click', once 处理器)
          → taskDiv.click()（模拟用户点击打开播放器）→ resolve
```

### 5.2 播放器初始化 initPlayer（video.ts:128-149）

1. 按配置 `video_mute` 设音量；`video.muted=false`（后续 clickPlayButton 内再临时静音绕过自动播放策略）。
2. `watchPlaybackRate()`：监听 `ratechange`，若 `playbackRate !== 配置值` 立即改回（对抗平台重置）。
3. `waitForVideoSourceAndPlay()`：每 1s 检查 `src/currentSrc/source/readyState`，最多 20 次；就绪后设倍速、`currentTime=0`，`auto` 开启时 `clickPlayButton()`；同时挂 `loadedmetadata/canplay`（once）兜底触发。
4. 500ms 后再次 `currentTime=0` 并设倍速（修复平台续播导致的时长不足）。

### 5.3 自动恢复与保活

- `setupVideoAutoResume()`：5s 轮询"auto 且 paused → clickPlayButton"；`pause` 事件 100ms 后恢复；`play` 事件 100ms 后重设倍速/静音。
- `clickPlayButton()`（video.ts:212-235）：先 `muted=true` 绕过自动播放策略 → 点击 `.vjs-big-play-button`（Video.js 大播放键）或直接 `video.play()`，失败回退点击按钮 → 恢复 `setMute()` 与 `setPlaybackRate()`。内部含播放点击限流 `PLAY_CLICK_MIN_INTERVAL_MS: 2000`（位于 playAborted 复活判断之后，2026-09 新增）——防止 loadedmetadata/canplay/源轮询三个事件源在 1 秒内各点一次播放按钮，令 DRM 播放器反复启停（伴随内存突刺）。
- **暂停风暴熔断（2026-09 新增，video.ts 与 scorm.ts 同构）**：`pause` 监听器顶部 `if (this.playAborted) return;`；60s 窗口内 pause ≥ 8 次（`PAUSE_STORM_MAX_COUNT / PAUSE_STORM_WINDOW_MS`）→ `abortAutoResume()` 并提示导出日志，防止"站点 pause ↔ 我们 play"逐秒死循环（切窗修复后理论上不再触发，留作其它原因兜底）。
- `startKeepAlive()`：播放 base64 内联 WAV 静音音频（loop，volume 0.001）维持浏览器媒体会话；`visibilitychange` 时若隐藏且暂停则重新 play。
- `setupVideoEndHandler()`：`ended`（once）→ 清理恢复轮询与保活 → `notifyVideoTaskComplete()` → `callEvent("complete")`。
- `notifyVideoTaskComplete()`：`localStorage['zsgl_video_complete_{courseId}_{jobIndex}'] = {status:"finished", courseId, taskId, timestamp}`（供每日积分模式监听，普通课程流程不依赖）。

### 9.4 单选排除法 SingleChoiceAnswerStrategy（exam-answer-strategy.ts）

```

  state = {questionId, triedOptions[], confirmedAnswer:null, options, originalQuestion}
```

### 9.5 多选两阶段 MultipleChoiceAnswerStrategy（utils/exam-answer-strategy.ts）

- **第一阶段 testIndividualOptions**：对每题按选项索引逐个单独提交（answerList 仅含该选项），据 `isCorrect` 归入 `correctOptions` 或 `wrongOptions`；通过 `progressCallback` 上报进度（testing 阶段）。
- **第二阶段 verifyCombinations**：将候选正确选项组合提交验证，确定 `finalAnswer` 并置 `isCompleted`。
- 结果经 `updateQuestionListWithMultipleChoiceAnswers` 回写题目数据，使 UI 提示路径复用同一答案来源。

### 9.7 考试答案自动勾选（exam_auto_select，2026-10 新增，T-022）

**范围与总约束**：把已破解出正确答案的题目自动勾选到页面上，**仅勾选、绝不提交**——只对选项元素执行 `unit.click()`，绝不触碰"上一题/下一题/交卷"按钮、绝不调用任何提交接口；ZsglQuestionTask 的交卷监听只匹配按钮文本，选项点击与其天然隔离，交卷监听/任务链/答案导出/破解策略零改动。开关 `exam_auto_select` 默认关闭，每次执行前运行时重读配置（`isExamAutoSelectEnabled`，`String()` 兼容 boolean/string，写法同 `answer_export_enabled`），关闭时立即停手。

**双向触发机制**：

- **正向（换题感知）**：`setupAutoSelectObserver()`（`Init()` 在 `setupReturnButton` 之后调用）注册 MutationObserver 回调 → `scheduleAutoSelect()`；开关关闭时**完全不注册 Observer、不做任何 DOM 操作**。Observer 挂 `document.body`（childList + subtree）而非题面容器：SPA 会重建 `.MuiPaper-root`，挂 body 免去容器重建后的反复重挂，匹配时再限定 `MuiPaper-root` 范围。防抖复用 `TimerManager.setTimeout` 按 key 覆盖语义（`DEBOUNCE_MS=300`），渲染瞬时抖动不触发匹配。
- **反向（答案就绪补勾）**：`crackQuestions()` 链尾 `answerMessage` 之后 fire-and-forget `autoSelectTick(true)`，覆盖"用户先翻题、答案后才破解就绪"的漏勾场景；`force=true` 忽略"已处理"缓存强制重查当前屏显题。

**执行入口 autoSelectTick(force)**：

1. 重读配置（关闭返回）+ `autoSelectBusy` 防并发；
2. `matchOnScreenQuestions()` 匹配屏显题——**唯一命中才动手**，零/多命中 Warn 跳过；
3. 目标集合 = `sectionRespList` 中 `isCorrect === "Y"` 的选项；**无 "Y" 视为未破解，绝不点击**，仅 Info 提示一次（`autoSelectLastUnansweredId` 去重）；
4. `collectOptionUnits` 收集选项——**为空时延迟重试**（题面与选项可能分帧渲染：`RETRY_DELAY_MS=800ms` 后 force 重查，最多 `MAX_RETRY=2` 次；耗尽则输出各选择器命中统计 Debug + Warn 放弃本轮）；`mapSectionsToUnits` 建立 section↔选项映射（失败放弃）；
5. **先占位 `autoSelectLastHandledId` 再点击**（勾选动作引发的 DOM 变更会再次进入 Observer 流程，防重入）→ `applyAutoSelect`。

**匹配算法**：在 `MUI_PAPER_ROOT` 范围内以归一化文本比对（`normalizeMatchText` = stripHtml + 去除全部空白字符）；匹配键双份（`getQuestionMatchKeys`：完整题干 + 最后一个 `<p>` 段落，任一命中即视为屏显）。同一题命中多个 Paper 时按归一化文本升序（内层优先）**优先选取含选项元素者**（选项总与真实题面同层），都无选项回退文本最短者。选项收集两级：① `collectOptionUnits` 合并原生 input 与 MUI 包装选择器（`OPTION_SELECTORS`），经 `closest(OPTION_CONTAINER_SELECTOR)` 提升去重；② 选择器未命中时 `findOptionUnitsByText` **按选项文本兜底定位**（实机确认：站点选项为自定义 div + React onClick 调 `onSelectOption`，选中态仅切 class，无 input/aria/MuiRadio 结构；且考试内容整体位于 `#examWatermark` 卡片内——第一轮"水印排除"方向系误判已撤销；**两遍式**定位：先收集全部"文本包含任一选项文本"的元素，再只保留最小命中者——单遍历即时去重会被文档序在前的选项容器挡住（实机第 4 轮 pageCount=1 勘误）；React 事件委托在根节点，点击文本后代即可触发选项 onClick；匹配语义分长短文本（实机第 5 轮勘误）：长文本包含匹配、**短文本（数字选项"7/15/30"、"对/错"）全等匹配**——minLen 只约束包含分支，纯数字选项不再被过滤）；section↔选项对应（`mapSectionsToUnits`）以归一化文本匹配优先，匹配不全且两侧数量一致才按 DOM 顺序对应（**该回退待实机校准**），数量不一致放弃本次勾选。

**幂等勾选 applyAutoSelect（按状态源分流）**：

- 可回读（input/aria-checked/Mui-checked 任一）：差集路径——S/T 只点目标项（radio 互斥自动取消原选中）；M 先取消不在目标集合中的已选项（含服务端试探答案的回显）再点目标项；已满足不动作；勾后 `VERIFY_DELAY_MS=200ms` 回读验证（`isOptionSelected` 三级回退）；
- 不可回读（站点自定义控件，第一轮实机确认）：一次性应用语义（`autoSelectAppliedIds` 按 questionId 防重复点击），只点目标项；点击经 `clickOptionUnit` 优先内部 input/label、否则点单元自身（React 委托在根节点，点后代同样触发）；以"点击前后**祖先链 class 签名**是否变化"（`ancestorChainSignature`，单元→题面容器）做**弱验证**——用户提供的考试页 DOM 证实选中态 class 挂在选项行级祖先、文本单元自身不变，故须对比整条祖先链；未变化 Warn + 面板降级提示正确答案。

**降级策略**：勾后验证失败 / 弱验证未通过（自定义控件点击前后样式未变化）→ Warn + Info 面板提示该题正确答案文本（回落既有答案展示路径）；重试耗尽仍未找到选项元素（附 `logOptionSelectorDiagnostics` 各选择器命中统计 Debug，供校准 `OPTION_SELECTORS`）/ 选项映射失败 → Warn 跳过本次勾选，不影响人工作答。

**生命周期**：`Stop()` 先 `stopAutoSelect()`（disconnect Observer + 清 `autoSelectDebounce` 防抖与 `autoSelectRetry` 重试定时器）再 `timerManager.clearAll()`，避免断开前的最后一次 DOM 变更又排入新的防抖任务。

### 10.1 状态模型

### 10.2 消息协议（window.postMessage，同源）

| 方向 | type | 载荷 | 处理 |
|------|------|------|------|
| 面板 → 任务 | `CONFIRM_START_TASK` | learningLimit/contributionLimit/interactionLimit/taskDelay(秒)/knowledgeLink | 更新 targets/taskDelay/knowledgePageUrl → `executeTaskAfterConfirm()` |
| 面板 → 任务 | `REFRESH_POINTS` | - | `handleRefreshPoints()`：重取 sid → 拉积分详情 → 广播 POINTS_UPDATED |
| 面板 → 任务 | `STOP_DAILY_POINTS` | - | `stopTask()` |
| 任务 → 面板 | `POINTS_UPDATED` | 三类积分状态 | 刷新面板 |
| 任务 → 面板 | `TASK_STOPPED` | - | 面板复位 |

### 10.3 主控流程

- `executeTaskAfterConfirm`：提取 pageId（knowledgePageUrl 或当前 URL 的 `/knowledgePage/([A-Fa-f0-9]+)`）→ 提取 sid（localStorage `sessionInfo.sid`，兜底遍历含 "session"/"sid" 的键，再兜底 16 进制长串）→ 拉积分详情 → 全满则停止 → `switchToNextTask()`。
- `switchToNextTask`（dailyPoints.ts:681-721）：`isSwitching` 防重入；循环 `getNextTask()`（优先级 knowledgeShare → knowledgeRead → course，对应积分未满且前置条件满足）→ 执行对应任务 → 无任务可做或 isTaskStopped 退出。
- **知识类任务**（executeKnowledgeReadTask / executeKnowledgeShareTask，逻辑同构）：`pointsGap = target - current`（target=0 视为已满）；循环调 API，每次成功 `accumulated += 0.6`、`callCount++`；每 5 次 `fetchPointsDetail` 校准并重算 gap；间隔 `getRandomDelay()` = taskDelay ± 5s 随机；终止条件：isTaskStopped / gap≤0 / needSwitchTask（连续 2 次积分详情 JSON 无变化）。
- **课程任务**（executeCourseTask）：分页拉 `courselist.do`（每页 30，sortType=2）→ `findUnfinishedCourseFromData`（`isCompleted === 0 || "0"`）→ `setTaskStarted(courseId)` 写 `zsgl_daily_task_{id}`（30min 过期）→ `openCourseInNewWindow`（`#/home/courseDetail/{id}`）→ `waitForTaskComplete`（storage 事件 + 3s 轮询双通道，30min 超时）→ 完成则继续下一课程，超时退出循环。
- **视频完成联动**：`setupVideoCompleteListener` 监听 `zsgl_video_complete_*`（storage + 5s 轮询双通道）→ `handleVideoTaskComplete(courseId)`：拉积分详情 → 学习积分达 target → `notifyCloseCourse`（写 `zsgl_close_course_{id}`）→ `stopTask()`。
- **stopTask**：置位停止标志、clearAll 定时器、abort 进行中请求、移除 message/storage 监听、保存状态、广播 TASK_STOPPED。

```
sign    = md5(signStr)
```
